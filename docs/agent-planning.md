# 주택사업 손익관리 의사결정 플랫폼 — 에이전트 기획안

> "수주부터 준공까지, 사업 변화에 따른 손익을 살아있는 데이터로 관리하는 주택사업 의사결정 플랫폼"

작성일: 2026-09-21

---

## 1. 문제 정의 (요약)

- 주택사업 손익표를 담당자가 **엑셀로 수기 작성·관리** → 휴먼에러, 반복작업, 시나리오 비교 불가.
- 공사비·금융비·PF·분양 조건이 자주 바뀌는데, 변수 하나 바뀌면 손익표를 **전면 재작성**.
- 검증이 **경험 많은 담당자 1인에 의존** → 부재 시 손익 왜곡 리스크.

## 2. 해결 방향

정적 엑셀 손익표를 → **변수 입력 기반 동적 시뮬레이션 + AI 판단보조 플랫폼**으로 전환.

핵심 3축:
1. **변수 기반 손익 계산 엔진** — 변수만 바꾸면 손익·Cash Flow 즉시 재계산.
2. **버전/시나리오 관리** — 입찰시(Baseline)/현재(Current)/전망(Forecast), Best/Normal/Worst 저장·비교.
3. **AI 에이전트 (Claude)** — 손익 악화 원인 분석, 영향도 높은 변수 우선순위, Cash 부족 구간 경고, 의사결정 코멘트 자동 생성.

---

## 3. 사용자 & 핵심 시나리오

| 사용자 | 상황 | 기대 |
|--------|------|------|
| 사업관리 담당자 | 매달 실적 반영 | 직접비 입력 → 손익·Cash 자동 갱신 |
| 사업 검토자 | 수주 준비 | 조건 바꿔가며 시나리오 비교 후 사업성 판단 |
| 협상 담당자 | 조합 사업비/도급증액 협상 | 즉석에서 조건 변경 시뮬레이션 제공 |
| 비숙련 담당자 | 담당자 부재 대체 | AI 코멘트로 판단 근거 확보 |

**대표 흐름**: 프로젝트 선택 → 변수 입력/수정 → 손익·Cash Flow 즉시 계산 → 버전/시나리오 저장 → AI가 원인·리스크·의사결정 코멘트 생성 → 버전 간 비교.

---

## 4. 데이터 모델 (핵심)

```
Project (사업)
 └─ Version (Baseline / Current / Forecast)
     └─ Scenario (Best / Normal / Worst)
         ├─ Inputs (변수 집합)
         └─ Result (계산 결과: 손익표 + Cash Flow)
```

### 4-1. 변수(Inputs) 예시
- **매출**: 분양가, 세대수/분양면적, 분양시기(공정), 분양률
- **원가(직접비)**: 토지비, 공사비(도급액), 설계·감리비, 기타 직접비
- **간접비**: 판관비율, 예비비
- **금융**: PF 금리, 대출한도, 이자 기간, 분담금/기성불 조건
- **공정**: 착공~준공 일정, 기성 지급 스케줄

### 4-2. 결과(Result)
- 손익표: 매출 − 원가 − 간접비 − 금융비 = 영업손익 / 세전손익
- Cash Flow: 연도(또는 분기)별 유입·유출·누적잔고, **부족 구간(음수) 탐지**

---

## 5. 손익 계산 엔진 (MVP)

- 순수 함수: `calc(inputs) -> {pnl, cashflow, kpis}` (백엔드 Python, 프론트 미러링 가능).
- 초기 MVP는 **엑셀 로직을 파이썬 함수로 이식** (핵심 항목 위주, 단순화된 공식).
- 결정적(deterministic)·테스트 가능하게 설계 → 검증 신뢰성 확보.
- KPI: 총매출, 총원가, 영업이익, 영업이익률, 최대 Cash 부족액/시점.

---

## 6. AI 에이전트 역할 (Claude API)

계산은 엔진이, **해석·판단보조는 에이전트**가 담당. (환각 방지: 숫자는 엔진 결과만 입력으로 전달)

| 기능 | 입력 | 출력 |
|------|------|------|
| 손익 악화 원인 분석 | 두 버전/시나리오의 결과 diff | "영업이익 −12억, 주요인: 공사비 +8%, PF금리 +1.5%p" |
| 영향도 변수 우선순위 | 변수 민감도(엔진이 ±10% 흔들어 산출) | 영향 큰 변수 순위 리스트 |
| Cash 부족 경고 | Cash Flow 시계열 | 부족 발생 구간 + 원인 + 대응 제안 |
| 의사결정 코멘트 | 시나리오별 결과 | "Worst 기준 준공손익 흑자 유지, 수주 권고" 등 |

- 구현: 엔진 결과(JSON) → 구조화 프롬프트 → Claude → 요약/코멘트 텍스트.
- **민감도 분석은 엔진이 수치로 계산**하고, AI는 그 수치를 설명하는 역할로 한정.

## 7. 시스템 아키텍처

```
[React + Tailwind]  변수입력 · 손익/CashFlow 시각화(Recharts) · 버전/시나리오 비교
        │ REST
[FastAPI]  계산 엔진 · 버전/시나리오 저장 · AI 오케스트레이션
        │
   ├─ 계산 엔진(pure python)
   ├─ 저장소 (MVP: SQLite/JSON, 확장: DB)
   └─ Claude API (해석·코멘트)
```

향후 확장(분리 과제): ERP/공정관리 시스템 연동(직접비 실시간), 과거 데이터 학습 기반 간접비 자동추정.

## 8. API 설계 (초안)

| Method | Path | 설명 |
|--------|------|------|
| POST | `/projects` | 사업 생성 |
| GET | `/projects/{id}` | 사업 + 버전/시나리오 조회 |
| POST | `/projects/{id}/calc` | 변수 입력 → 손익·CashFlow 계산 |
| POST | `/projects/{id}/versions` | 버전/시나리오 저장 |
| GET | `/projects/{id}/compare?a=..&b=..` | 두 버전 비교 diff |
| POST | `/projects/{id}/ai/analyze` | AI 원인분석·코멘트 생성 |
| POST | `/projects/{id}/sensitivity` | 변수 민감도 분석 |

## 9. 화면 구성

1. **대시보드**: 사업 목록 + KPI(영업이익률, Cash 부족 여부) 요약.
2. **손익 편집**: 좌측 변수 입력 폼 / 우측 손익표·CashFlow 차트 실시간 반영.
3. **시나리오 비교**: Best/Normal/Worst 나란히, 버전 diff.
4. **AI 인사이트 패널**: 원인분석·변수우선순위·Cash경고·의사결정 코멘트.
